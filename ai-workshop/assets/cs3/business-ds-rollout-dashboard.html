CTA label proliferation & repetitionMEDheuristic

Homepage exposes 8 distinct CTAs including repeated "Explore…" and two "Learn More" labels. Generic verbs ("Learn More") give screen-reader and scanning users no destination cue, and compete with the single solid-blue primary ("Talk to an Expert"). Reserve the filled style for one primary action per view; make secondary labels specific ("Explore Business Monitors" is good, "Learn More" is not).

Consent overlay is the first interactive layerLOWheuristic

The cookie banner (.cky-*) gates the hero. Expected for GDPR, but confirm it doesn't trap keyboard focus and that a one-click privacy-preserving path exists (a reject control is present). It competes with the hero for the 2-second read.

Priority recommendations
  1. Fix the shared nav/footer link component — clears axe link-name (serious) across the whole vertical in one change. Highest leverage, lowest effort.
  2. Add a single H1 to every product hub — orientation + SEO, confirmed by axe on every audited page.
  3. Darken --brand-blue to clear AA with headroom, fix base paragraph weight, and reconcile the link blue so the page actually uses the token — where the rollout and contrast findings meet.

Method & limitations
  • Token signal: counted CSS custom properties matching --brand-* in each page's accessible stylesheets, benchmarked against product-a (30 tokens) as the migrated reference. The shared Figma file is a cover page only, so exact hex/spacing token values could not be enumerated via MCP — token presence and naming family were verified, not every value.
  • Accessibility: axe-core 4.10.2 was injected and run on 8 pages (5 lowest-completeness product pages + all 3 solutions pages), so those findings are deterministic with cited rule IDs. The other 8 sampled pages were not axe-scanned; their a11y signals remain heuristic. axe automated rules cannot catch everything (focus order, keyboard traps, meaningful alt text quality) — manual testing still required.
  • Performance: no Lighthouse run. Page-weight signals (e.g. the 379-image LCD page) are observational from a single render, not Core Web Vitals.
  • Scope: 16 pages sampled from 21 discoverable via the Business nav. The site sitemap.xml returned empty; a deeper crawl would surface product-detail and regional variants not covered here.
  • Rate limiting / infra: earlier intermittent nginx 404s on the newer solutions pages were a reverse-proxy issue, now resolved — solutions-d and solutions-b2 have since been fully fingerprinted. axe on the three newer pages remains outstanding (CSP-blocked), not a data gap in the completeness scores.
